# PR #17 Review

## Summary

Diff review of [PR #17](https://github.com/elegantchaos/AgentTools/pull/17), head `124b0cf2b2d7c7834023ab988da30747b9e87044`, against `1d53f53c4bd79423bca134395141ba8dc7fda05c`. The change adds repository Markdown link checking and historical-link repair. **Needs rework:** six confirmed correctness findings affect which revision is selected, which text is rewritten, and whether checks pass or fail.

## Findings

### 1. Should Fix — Search Commits Where The Target Changed Too

`Sources/AgentToolsCore/Links/LinkingFileHistory.swift:28,52–59`

The search visits only commits that changed the linking document. A target can first appear while an unchanged document already carries its link. That commit qualifies under the documented contract, but the search never examines it.

Confirmed with four commits: create the journal link while its target is absent; add the target; revise the target; delete the target. The repair chooses the third commit, reports a fallback, and serves the revised text. The promised answer is the second commit, where the link first resolved. Include target-existence transitions within each interval where the document carries the link; use the fallback only when no qualifying commit exists. Add this history as a regression case.

### 2. Should Fix — Exclude Code And Escaped Literal Text Before Rewriting

`Sources/AgentToolsCore/Links/MarkdownLinkScanner.swift:12,17,28–30,39–46`

Code-span state is confined to one line, and the inline expression starts at `](` without checking for a valid opening bracket. Consequently a multiline backtick span containing `[old](../../Old.md)`, and the literal text `\[literal](../../Old.md)`, are both treated as links.

Confirmed with a journal containing those two examples while `Old.md` existed, followed by its deletion. `--fix-history` rewrites both examples and reports two fixes. Parse the enclosing Markdown context, including multiline code spans and escaped brackets, before offering destinations for checking or mutation. The same scanner feeds checking, historical matching and rewriting, so cover all three consumers. Multiline code spans and punctuation escapes are defined by [CommonMark code spans](https://spec.commonmark.org/0.31.2/#code-spans) and [backslash escapes](https://spec.commonmark.org/0.31.2/#backslash-escapes).

### 3. Should Fix — Recognise Links And Reference Definitions Across Lines

`Sources/AgentToolsCore/Links/MarkdownLinkScanner.swift:13,17,29`

Scanning each line independently misses an inline destination beginning on the line after `](`, and a reference destination beginning on the line after `[label]:`. Both are valid Markdown forms.

Confirmed with a tracked README containing `[broken](` followed by `Missing-multiline.md)`, plus `[label]:` followed by an indented `Missing-reference.md` and a use of `[label]`. Both targets are absent, yet the command exits successfully with `0 broken, 0 unverified`. Scan complete constructs across line boundaries, retaining source ranges and start-line diagnostics. See [CommonMark links](https://spec.commonmark.org/0.31.2/#links) and [reference definitions](https://spec.commonmark.org/0.31.2/#link-reference-definitions).

### 4. Should Fix — Decode Markdown Destinations Before Resolving Paths

`Sources/AgentToolsCore/Links/MarkdownLink.swift:22–27`

Only URL percent escapes are decoded. Markdown backslash escapes and character references remain in the filesystem path, although renderers resolve their decoded destinations.

Confirmed with existing tracked files `a(b).md` and `a&b.md`: `[escaped](a\(b\).md)` and `[entity](a&amp;b.md)` are both reported broken. Normalise Markdown escapes and entities before splitting and percent-decoding the URL, while preserving the original source text and replacement range. Use the same decoded destination for current checks and history matching. See [CommonMark links](https://spec.commonmark.org/0.31.2/#links).

### 5. Should Fix — Preserve Case-Exact Checks Inside Submodules

`Sources/AgentToolsCore/Links/RepositoryIndex.swift:63–65`

Checked-out submodules bypass Git's path listing and use `fileExists` directly. On a case-insensitive filesystem, a wrong-case path therefore passes, contradicting the command's advertised behaviour.

Confirmed on this Mac with a tracked gitlink containing `README.md` and a parent README linking to `Module/readme.md`: `agt links` reports `0 broken, 0 unverified`. Index checked-out submodule contents case-exactly, including nested submodule boundaries; retain the unverified result for unavailable checkouts. Add a test distinguishing this from the existing unchecked-submodule test.

### 6. Should Fix — Include Submodule Ancestors In Present Directories

`Sources/AgentToolsCore/Links/RepositoryIndex.swift:37–45`

Gitlinks are removed from the files collection before parent directories are derived. A directory containing only submodules is consequently absent from `directories`, and it cannot match the later test for a path inside a submodule.

Confirmed with a tracked gitlink at `Packages/Module` and `[parent](Packages)` in the root README: the existing `Packages` directory is reported broken. Derive ancestor directories from gitlink paths as well as ordinary files. Cover checked-out and uninitialised submodules; the parent exists in the repository tree in either case.

## Codebase Effect

### Made Obsolete

**No additional removal is needed.** `GitQuery` replaces the private process invocation in `WorktreeCreator`; the old subprocess implementation was removed. Repository-wide searches found no competing Markdown scanner or historical-link repair mechanism in this repository. The Bookish prototype described by the PR is outside this review's codebase scope.

### Simplification Now Possible

**No additional consolidation is recommended.** The new lexical `RepositoryPath` rules enforce repository containment and Markdown root-relative semantics. Validation's `resolvePath` instead accepts filesystem-absolute and home-relative user options; replacing it with these rules would change its contract. The links result types keep checking, resolution and mutation separate without introducing a second owner of link state.

### Duplication

**No wider refactor is needed for this PR.** `FormatTool.swiftFiles` also lists Git paths, but selects tracked and untracked Swift source and applies formatting exclusions; `RepositoryIndex` scans tracked Markdown and separately indexes possible destinations and gitlinks. Those are different selection policies. `GitQuery` owns literal pathspec handling for its consumers; format's intentional `*.swift` pathspec must retain wildcard interpretation.

### Design Clarity

**Keep a single Markdown interpretation shared by all three consumers.** `LinkChecker`, `LinkingFileHistory.links(at:)`, and `LinksTool.rewrite` already use the same scanner, so fixing that boundary can correct current checks, history recognition and mutation together. Preserve that ownership while addressing the findings. The command remains in `AgentToolsCore`, runs in the selected checkout, and is excluded from the self-responsible permission-bearing command root. The changed `WorktreeCreator` helper retains trimming at its call boundary and does not change setup ownership or escalation policy.

The journal has no complete full-package review, but this change's remaining defects are concentrated in the newly reviewed Links boundary. A full AgentToolsCore review is not required to resolve them; this review makes no claim of full-package coverage.
