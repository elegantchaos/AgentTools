# 2026-09-30

## Open bug: a workspace member that is also referenced elsewhere has no test action

Sam wants this fixed properly in `agt`, but there was no time to do it now. Bookish works around it with a configuration exclusion, and this entry is the starting point for the real fix.

- Found on Bookish. Making Xcode run the package tests meant adding the nine Bookish packages that are part of the product to `Bookish.xcworkspace` as `group:` members, because a shared scheme's testable, `container:Dependencies/<Package>`, is dropped silently when that container is not in the workspace. The submodules (`Application`, `Commands`, `Icons`, `Logger`) already worked that way. With the packages listed, `xcodebuild test -workspace Bookish.xcworkspace -scheme Bookish` ran all 350 tests in 15 bundles, so that part works.
- Full validation then failed at `test BookishLookup (macOS)`: `xcodebuild -workspace Bookish.xcworkspace -scheme BookishLookup ... test` answered "Scheme BookishLookup is not currently configured for the test action." `agt validate --plan` had promised "tested, with scheme BookishLookup", and the same for `BookishDatastoreUI`, `BookishCleanup`, `BookishImporter` and `BookishApp`. `BookishRecord` and `BookishCoding` have no workspace scheme at all ("does not contain a scheme named"), yet the plan said "tested, in its own directory" for `BookishRecord`, so the route depends on which schemes Xcode happens to list.
- The assumption that breaks is the 2026-09-25 rule, implemented in `ValidationDiscovery.rootPackages`: a package that is a workspace member is a root, and a root gets a test action. It does not hold when the package is also referenced by an `.xcodeproj` (`XCLocalSwiftPackageReference`) or depended on by another member. All nine Bookish packages are in that position: seven are referenced by `Bookish.xcodeproj`, and `BookishLookup` and `BookishRecognition` are only dependencies of `BookishApp`, which is itself a member and a project reference. The doc comment on `rootPackages` already says such packages get build-only schemes, so the function contradicts its own comment. ActionStatus and ClockSync, where the 2026-09-24 and 2026-09-25 checks ran, do not combine these.
- Not established: which of those two conditions is the trigger, because every Bookish package meets at least one, and `BookishLookup` and `BookishRecognition` failed with only the dependency one. Testing it needs a fixture with a package that is a workspace member and only a dependency, and one that is only a project reference.
- Bookish's workaround is `validate.excludePackages` in `.agt/config.json`, naming the nine packages, on the `feature/https-thumbnails` branch (Bookish PR #42). Their tests still run through the Bookish scheme's testables on macOS and iOS. `--fast` validation is unaffected, because the exclusion list is used only by the full plan and the `--plan` summary; `fastSteps` takes no exclusion list, so it still tests a changed package with SwiftPM. To reproduce, remove the exclusion and run `agt validate --plan` and `agt validate`.

### Ideas for the fix

- Root only when nothing else owns the package: a workspace member counts as a root only if no project references it and no other member or package depends on it. This matches the `rootPackages` comment, and is the smallest change.
- Fall back at run time: when `xcodebuild` reports "not currently configured for the test action", run that package in its own directory instead. The 2026-09-25 entry found that probing with `-showTestPlans` lies about this, so the error message is the only reliable signal, and a fallback costs a wasted `xcodebuild` start.
- Treat a package as covered when the product scheme's testables already list its test targets, and skip the separate step. That is the state Bookish wants: one run, in one place, sharing the product's build. It needs the scheme files read at discovery, which the 2026-09-24 entry notes are not in the fingerprint.
- Whichever is chosen, add a fixture with a workspace member that a project also references, and make `--plan` say so when a scheme has no test action.
- When it is fixed, Bookish can drop the exclusion if it wants the packages tested separately as well.
