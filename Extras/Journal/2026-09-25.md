# 2026-09-25

- Step 5 of the validation plan: full validation in the background (`--background`, `--status`, `--wait`), released as 3.6.0.
- The background worker is the same `agt` binary with a hidden `--background-worker` flag, detached into its own process group with SIGHUP ignored, so it outlives the agent's shell. Its state is a small JSON record in `.build/agt/background/status.json`.
- Results are keyed by a working-tree fingerprint: the index copied to a temporary file, `git add --all`, `git write-tree`, plus the same tree for each dirty submodule. It covers untracked files, ignores ignored ones, and never touches the real index.
- Superseding is cooperative. A new run writes a fresh token into the status record; the worker checks it before each step and about twice a second during one, sends SIGINT to its current command, and exits. Killing the process group is only a fallback after 30 seconds: SwiftPM and `xcodebuild` put their children in other groups, so killing ours would leave them running, whereas an interrupted `xcodebuild` cleans up after itself. On ActionStatus, a foreground `--fast` stopped a background `xcodebuild` mid-build and finished in 18.5 s, with nothing left running.
- Bug found on the way: the worker inherits `--clean`, which removed `.build/agt` including its own status record. `--clean` now keeps `background/`.
- Bug from Bookish: full validation tested BookishLookup through the workspace's `BookishLookup` scheme, and `xcodebuild` refused with "not currently configured for the test action". Xcode gives a package's schemes a test action only when the package is a root: a workspace member (`group:` or `absolute:` in `contents.xcworkspacedata`), or the package opened directly. Packages that a project references, or that are only dependencies, get build-only schemes; `-showTestPlans` lies about them, so probing is no use. Discovery now keeps a container scheme for a package only when the package is a root or a shared scheme file with that name has testables; other packages test in their own directory.

## Test simulators and output fixes (3.7.0)

- Simulator tests use a platform's test device for its newest installed runtime, following Sam's convention of simulators kept for testing, extended with the OS version: `Test iPhone 27.2`, `Test iPad 27.0`, `Test TV 27.0`, and `Test Watch`/`Test Vision` for the other platforms. The newest runtime comes from `simctl list -j runtimes`, since a runtime with no devices yet does not appear in `-showdestinations`.
- Sam picks test devices for App Store screenshots: the existing ones were iPhone 17 Pro Max (6.9-inch) and iPad Pro 13-inch (M5) (16GB), and Apple TV 4K (3rd generation) at 4K. A new device uses the newest type matching that rule, since `simctl` lists device types newest first: Pro Max, `iPad Pro 13-inch`, Apple TV 4K not at 1080p, and Apple Watch Ultra (the largest watch screenshot size).
- A missing test device is created with `simctl create` for the preferred family (iPhone for iOS), unless a simulator with that name already exists, which stops duplicates when `-showdestinations` does not list it. Creating a simulator changes the machine, not the project, so it does not break the "validation never modifies the project" decision.
- One-off: renamed the existing `Test iPhone`, `Test iPad` and `Test TV` (all iOS/tvOS 27.0) to `Test … 27.0`. Bookish's plan then created `Test iPhone 27.2` (iPhone 18 Pro Max), and ActionStatus with every platform created `Test Watch 27.0` (Apple Watch Ultra 4 (49mm)) and reused the others.
- The simulator choice is cached under a new discovery key, and the notes are recomputed from it on every run, so they appear even when discovery is cached. A failed creation is reported once; later runs report the missing device from the cached choice until discovery reruns.
- Interrupted steps are recorded as STOP. Warning detection now requires `warning:` at the start of a line or after `: ` or `] `, is case-sensitive, and skips Swift Testing progress lines (which start with a symbol and quote test arguments). That drops this repo's own false `[warnings]`, which came from test arguments that are realistic warning lines, and `xcodebuild`'s `WARNING:` about multiple matching destinations.

## CI fix: commands move into `AgentToolsCore`

- CI had failed on every push since 7c18a7f6 (2026-09-24). `swift test -c release` built fine, then ran `agt`'s own `main`, which rejected the test runner's `--test-bundle-path` argument. That commit changed the `@main` root command from `ParsableCommand` to `AsyncParsableCommand`. To test an executable target, SwiftPM renames its entry point in the test build. With Swift 6.3.3 (Xcode 26.6 on the `macos-26` runner), that rename misses an async `@main` in release. Swift 6.4 (Xcode 27) handles it, so local release tests passed.
- Fix, recorded as [decision 0004](../Decisions/0004-executable-is-only-an-entry-point.md): everything except the entry point is now the `AgentToolsCore` library, and the tests import it. The `AgentTools` executable target holds only `AgentToolsMain`, which runs `AgentToolsCommand` (renamed from `AgentTools` to match its file, and made public). No test build links an executable's `main` any more, on any toolchain.
- The Versionator plugin moved with `ToolVersion` to `AgentToolsCore`. `Bundle.main` in `BackgroundLauncher` still resolves to the `agt` binary at runtime.
