# Run agt Outside Claude Code's Sandbox

Agents in Claude Code and Codex kept failing `agt` runs until they repeated them unsandboxed. A sandboxed probe from a Bookish session found why writable paths were never going to be enough. Package builds and tests, and the macOS app scheme through `agt validate --target Bookish`, all worked inside the sandbox, but full validation stopped at its first step: its validation checkout is a git worktree, and the sandbox keeps the repository's `.git/worktrees` read-only. Beyond that, `xcrun simctl list` and every simulator destination failed with "CoreSimulatorService connection became invalid … Connection refused". The simulator service is reached through a system service connection that the sandbox refuses, so iOS tests cannot run inside it whatever is writable. A clone-based validation checkout was considered and dropped: it would make only a macOS-only full run possible in the sandbox, which nothing uses.

Codex already runs `agt` outside its sandbox through allow rules from the Agents repository. Claude Code's allow rules only skip the permission prompt; the setting that takes a command out of its sandbox is `sandbox.excludedCommands`, which was never set. [Claude Code's sandboxing documentation](https://code.claude.com/docs/en/sandboxing) says entries use `Bash(...)` rule syntax, so `agt *` matches with or without arguments, that an absolute path does not match the bare name, and that every command in a call must match: a `cd`, a redirect to a file or a command substitution keeps the whole call sandboxed.

`agt sandbox configure`, and so `agt refresh`, now adds `agt *` and `rt *`, and the same under `~/.mint/bin`, to `sandbox.excludedCommands`, merging with existing entries as it does for `allowWrite`. Tests were written first and failed on the missing behaviour; targeted validation then passed all 323 tests. Sam asked for the change after the probe; whether Codex's allow rules take effect for compound `agt` commands is being checked separately in a live Codex session.
