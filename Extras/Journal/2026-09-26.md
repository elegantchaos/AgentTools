# 2026-09-26

## Runtime crash on macOS 26: swift-collections 1.7.1 (3.7.1)

- `agt` 3.7.0, installed by Mint with Xcode 27.0 RC (Swift 6.4) selected, aborted at launch on macOS 26.6.2: `dyld: Symbol not found: _swift_initBorrow`, expected in `/usr/lib/swift/libswiftCore.dylib`. It built fine; the failure was only at runtime.
- The package's own deployment target was still macOS 26. The reference came from swift-collections 1.7.0, which `swift-configuration` depends on directly and through `swift-service-lifecycle` and `swift-async-algorithms`. Under `#if compiler(>=6.4)`, its `InternalCollectionsUtilities` module compiles `Optional._borrow`, marked `@available(SwiftStdlib 6.4, *)` (macOS 27). Swift 6.4 still links `swift_initBorrow` strongly instead of weakly, so the binary needs a runtime function that only exists in macOS 27. Swift 6.3.3 (Xcode 26.6) never compiles that code, so its builds, and CI's, were fine.
- swift-collections 1.7.1 removes the unused `Optional._borrow`. Built with Swift 6.4 against it, `agt` has no `swift_initBorrow` reference (the remaining borrow-related symbols are weak) and runs on macOS 26.
- `Package.swift` now depends on swift-collections directly, `from: "1.7.1"`, so re-resolving can never return to 1.7.0, with a comment explaining why the unused dependency is there. SwiftPM does not warn about it. The swift-argument-parser and swift-configuration minimums were raised to the versions already resolved and tested (1.7.1 and 1.2.1).
- CI adds an Xcode 27 job on the `xcode-27` runner (the `macos-26` image has no Xcode 27) that builds and tests in release and uploads `agt`. The `xcode-27` runner is macOS 27, where the symbol exists, so a second job downloads that binary and runs `agt --version` on `macos-26`. That is the combination that crashed.
